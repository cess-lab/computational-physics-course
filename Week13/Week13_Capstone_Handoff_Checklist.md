# Week 13 Capstone Handoff Checklist

Use this checklist after the group evidence is complete and before the post-submission question slot and individual member are drawn.

## Scope and model

- [ ] One narrow physical question is stated.
- [ ] The approved problem space and starter Live Script are named.
- [ ] Assumptions, variables, parameters, outputs, and units are recorded.
- [ ] One parameter or assumption is changed; the other important inputs are identified as fixed.
- [ ] The prediction was written before the modified output was viewed.

## Algorithm, code, and output

- [ ] Short pseudocode maps inputs to method, output, checks, and interpretation.
- [ ] One relevant starter-code section is traced line by line.
- [ ] The traced line is connected to both an algorithmic step and a physical quantity.
- [ ] One principal graph or table answers the physical question directly.
- [ ] Axes, quantities, units, cases, and the changed parameter are labelled.

## Validation and interpretation

- [ ] The required check from the approved plan is shown with concrete evidence.
- [ ] The chosen check uses different evidence or tests a different weakness.
- [ ] Each check states what it supports and what it cannot establish.
- [ ] The physical conclusion answers the original question and matches the prediction.
- [ ] One numerical or model limitation is stated.

## Fresh-session reproducibility

- [ ] The edited starter Live Script and every required input file are together.
- [ ] Numerical settings, parameter values, assumptions, and units are recorded.
- [ ] Run order and MATLAB release are recorded.
- [ ] A teammate has rerun the final bundle from a fresh MATLAB R2025a-or-later session.
- [ ] The principal output and both validation results were regenerated.
- [ ] Any repair made during the clean rerun is recorded.

## AI and individual defence

- [ ] AI use is declared, or the record states that no AI was used.
- [ ] The request, accepted/modified/rejected decision, reason, and independent checks are recorded.
- [ ] Each member has a relevant code trace and physical explanation ready.
- [ ] The lecturer's rotation ledger gives every member a first completed defence before a second entry.
- [ ] Any absence remains pending until a make-up defence is recorded.
- [ ] The final submission state is changed to LOCKED only after all evidence and the clean rerun are complete.

Google Classroom remains the official submission and feedback record. Follow the lecturer's posted coursework and deadline; this local package does not create or modify Classroom/Forms items.
