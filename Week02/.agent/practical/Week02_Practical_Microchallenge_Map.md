# Week 02 Microchallenge Map and Diagnostic Guide

The ten slots below follow the exact student challenge sequence. Cooling supplies six linked steps, decay supplies a second exponential-loop context, and the oscillator supplies a third loop context before the cross-context synthesis.

| Slot | Context and intended progression | Instructor reference / expected evidence | Diagnostic look-fors |
| --- | --- | --- | --- |
| 1 | **Cooling — prediction.** `T(t)=T_room+(T0-T_room)exp(-t/tau)`, with 25 °C, 85 °C, 4.0 s. | Predict `T(0)=85 °C`; temperature falls because `T0>T_room`; as time grows it approaches 25 °C. | Flag a curve that rises, tends to 0 °C, or claims the room temperature is reached exactly at a finite time. Ask which term is the equilibrium value. |
| 2 | **Cooling — inputs and pseudocode.** Build `0:1:16` s and order inputs, storage, loop, current time, update, output, and check. | There are 17 time samples. `t_cool_s/tau_s` is dimensionless because both quantities are in seconds. | Check for mixed units, a missing input, a loop before the time array, or a plan with no output/check. Punctuation is less important than dependency order. |
| 3 | **Cooling — loop, trace, and graph.** Complete the loop and trace the first two passes. | With the supplied grid, pass 1 stores `T_C(1)=85.000000 °C` at 0 s; pass 2 stores `T_C(2)=71.728047 °C` at 1 s. A labelled time-temperature graph decreases toward 25 °C. | The second pass must use `sample_index=2`, `current_time_s=1 s`, and storage location 2. A scalar calculation may run while the array remains wrongly filled. Preallocation is a supported working-exposure step, not a code-volume target. |
| 4 | **Cooling — validation and one parameter change.** Check the initial value and double only `tau_s`. | Baseline: `T(0)=85 °C`, `T(16 s)=26.098938 °C`. With `tau_s=8.0 s`, `T(16 s)=33.120117 °C`; the revised curve cools more slowly but has the same initial and long-time limits. | Require a prediction before rerun. Reject “larger tau means higher equilibrium” because `T_room` is unchanged. The check should test the initial value and the approach to room temperature. |
| 5 | **Cooling — syntax defect.** Remove the final `end`, capture the error location, then restore it. | Corrected loop executes and reproduces the Q3 values. Error wording/location may vary by MATLAB release; the essential evidence is the missing block terminator, its consequence, and the corrected line. | Do not award the point for copying an error message alone. Look for a link between the reported location/surrounding lines and the incomplete `for` block. |
| 6 | **Cooling — indexing defect.** Replace the intended indexed store with repeated `T_C(1)=...`, inspect, then repair. | The wrong vector has one overwritten first entry (ending at the last loop value, about 26.098938 °C) and zeros elsewhere if preallocated. The repaired vector has 17 values, with the initial-value check restored. | This is a runnable but logically wrong program. Look for the distinction between `sample_index` and the physical current time, and for evidence that the defective output was kept separate from the repaired output. |
| 7 | **Radioactive decay — transfer the loop.** `N(t)=N0 exp(-lambda t)`, `lambda=log(2)/T_half`, with 800 counts and 6 h. | `lambda=0.115524530 h^-1`; the exponent is dimensionless; `N(0)=800`, `N(6 h)=400`, and `N(24 h)=50`. The graph decreases monotonically. | Do not treat non-integer model counts as a coding error. Check the sign, half-life units, hourly time grid, and whether the loop stores one result per hour. |
| 8 | **Decay — physical/logical defect.** Compare `exp(+lambda*t)` with the correct negative exponent. | The wrong version grows and gives 1600 at 6 h; the corrected version gives about 400 at 6 h. The half-life check is the decisive validation. | MATLAB reports no syntax error, so require a physical explanation: decay must reduce the amount and one half-life must halve it. A trend-only statement without the 6 h check is incomplete. |
| 9 | **Mass-spring oscillator — third context.** `x(t)=A cos(2 pi t/T)`, `A=0.080 m`, `T=1.60 s`, grid 0:0.1:3.2 s. | Loop output has `x(0)=0.080 m`; at quarter period `t=0.40 s`, `x≈0 m`. Negative displacement means the mass is on the opposite side of the chosen positive direction. | Trace the pass nearest `t=0.40 s`; do not call negative displacement negative distance. The graph should repeat after 1.60 s and the two stated checks should be explicit. |
| 10 | **Cross-context comparison and AI declaration.** Compare the repeated loop pattern and one physics-dependent defect across cooling, decay, and oscillation. | Expected comparison: preallocate, loop over a time array, read the current value, apply the supplied model, store by index, then validate. Accept a clear check such as `T(0)=T0`, the decay half-life, or oscillator initial/quarter-period value. AI record must state tool/use or “not used,” accepted/modified/rejected output, reason, and independent checks. | A working script is not enough. Look for one defect that an error message cannot expose (repeated index or wrong decay sign), a physical reason for the chosen check, and a concise—not full-chat—AI record. |

## Instructor validation summary

The minimum Core validation set is:

- cooling: initial value and qualitative approach to `T_room_C`;
- modified cooling: slower response when `tau_s` is doubled;
- decay: initial value plus the half-life result at 6 h;
- oscillator: initial value plus zero displacement at one quarter period.

The reference script contains executable versions of these checks. A group can receive model, algorithm, tracing, diagnosis, and interpretation credit with incomplete execution, but full computational-output credit requires reproducible output or a precise execution diagnosis.
