# Week 02 Practical: Instructor Protocol

## Purpose

The activity keeps the physics supplied and makes the new cognitive load algorithmic: ordered steps, loop tracing, one-parameter modification, and diagnosis of syntax, indexing, and physical/logical defects. Use the microchallenge map for question-level guidance and the reference script for numerical checks.

## Before the practical

1. Confirm that the student challenge is the current Week02 file and that the reference script runs independently with base MATLAB.
2. Form groups of two or three and record each member in the hidden rotation ledger. Encourage rotation of model, algorithm/code, and validation/interpretation roles.
3. Keep the existing Week02 diagnostic/Form/Classroom mapping unchanged. This support bundle is not a publication or replacement workflow.
4. Prepare one copy of the variant bank per question slot. Do not disclose post-submission variants before evidence is locked.

## During the investigation

- Groups complete all ten questions in one saved copy of the student challenge.
- For each question, look for the evidence named in the challenge: prediction; model and units; pseudocode or plan; runnable or diagnostic code evidence; validation; interpretation; and, where relevant, the AI decision record.
- Accept a precise diagnosis when execution fails. Do not require polished or independently designed code for pass-level credit.
- Reinforce the recurring pattern: inputs -> current value -> update -> stored output -> check. Ask students to connect an index and a loop pass to a physical time.
- Q5 must be restored after the missing-`end` demonstration. Q6's defective output must be stored in a new variable. Q8's plus-sign version must be compared with the corrected decay version.

## After submissions are locked

1. Draw a question slot for each group. When a slot is reused, assign a distinct variant from `Week02_Defence_Variant_Bank.md` and record its exact code in the ledger.
2. Within each group, select only an eligible member: no member receives a second selection until every member has one completed defence.
3. Ask the selected student to explain the supplied model, trace the relevant code/output, and answer the slot's validation, parameter, or defect follow-up. This is an explanation and verification check, not a MATLAB-function memorisation test.
4. Do not allow a new AI response during the spoken defence. The student may refer to the submitted group evidence.
5. Score the four defence dimensions in `Week02_Defence_Rubric.md`. If absent, record the assigned slot and mark the entry pending; schedule the same student for a make-up before counting the entry.

## Fairness and grading guardrails

- The group component uses the practical-portfolio rubric: model/units 15%, algorithm/pseudocode 20%, code reading/completion/modification 25%, validation 15%, physical interpretation/limitation 20%, and responsible AI decision record 5%.
- Full numerical-output credit requires reproducible output or a precise diagnosis of why execution failed. Full integrated evidence requires at least one valid check.
- Do not use AI-detection scores or complete chat histories as evidence. Judge the recorded decision, independent checks, trace, and defence.
- Keep stretch work optional: reusable functions from scratch, independent second checks, and advanced comparisons are not required for an ordinary pass.
