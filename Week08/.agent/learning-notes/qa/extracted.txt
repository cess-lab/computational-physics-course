ODE Simulation: Euler Steps for Newton Cooling
Turn a familiar rate law into small, visible temperature updates, then test how timestep size changes the
simulation.
Physical question. A hot object cools toward room temperature. Starting at 80 ◦ C in a 20 ◦ C
room, what temperature does an Euler simulation predict from 0 to 300 s, and how does the
timestep affect confidence in that prediction?

Core learning outcomes
1. identify the state, rate, initial condition, timestep, and final time in a first-order physical model;
2. trace and complete an Euler update loop that produces a labelled temperature trajectory; and
3. validate the simulation with smaller timesteps, an exact reference, and physical initial-value and trend
checks.

A common physical/logical defect. In the update, use the current value Tn on the right-hand

object has cooled. MATLAB can run that code, but the physics would be wrong.

4. Pseudocode before MATLAB
1. state the environment temperature, initial temperature, timescale, timestep, and final time with
units;
2. create all time positions from 0 to the final time using the chosen timestep;
3. reserve one temperature value for every time position, then place the initial condition in the first
position;
4. for each current position, calculate the cooling rate from the current temperature;
5. use Euler’s update rule to store the next temperature;
6. plot temperature against time with axis labels and units; and
7. check the initial value and trend, then compare the result with a smaller timestep and a reference.

7. Core validation: check the start, the trend, and the reference
The Euler trajectory with h = 50 s starts at the required 80 ◦ C, and its first two calculated values are
50 ◦ C and 35 ◦ C, as traced by hand. Every plotted trajectory decreases toward the 20 ◦ C environment
and remains within the physical bounds for this case.
Validation statement. At the same final time, the endpoint error decreases from 2.0497 ◦ C for
h = 50 s to 0.5531 ◦ C for h = 12.5 s. Together with the correct initial value and cooling trend, this
supports the finer Euler result for the stated Newton-cooling model.

8. Interpret the simulated trajectory
Temperature falls quickly at first because the difference T − Tenv is large. As the object approaches the
room temperature, the magnitude of the rate decreases, so the curve flattens. At 300 s, the exact model
predicts about 23.0 ◦ C: the object is close to, but has not reached, the environment temperature.
The numerical result is only as appropriate as its physical model. Here we assumed a constant environment temperature and one constant cooling timescale. Changing airflow, contact with another object,
or internal heat generation could make that assumption unsuitable.

Working exposure: supplied ode45 reference
MATLAB’s ode45 is a solver that can produce a reference trajectory without writing the Euler loop.
Read the supplied call as evidence, but Core work remains the visible Euler update and its validation:
1 coolingRate = @(t,T) -(T - T_room_C) / tau_s;
2 [t45_s,T45_C] = ode45(coolingRate,[0 t_final_s],T_initial_C);
3 plot(t45_s,T45_C,'k-')

The anonymous function states the same rate law. The interval [0 t_final_s] and initial condition
T_initial_C remain physical inputs that must be checked.

Optional stretch
Optional extensions include deriving formal Euler stability conditions, comparing Runge–Kutta methods,
simulating a stiff system, handling events, or coupling several nonlinear ODEs. These are not required
for the Core pathway.

Three takeaways
1. A first-order ODE simulation needs a state, a rate law, an initial condition, a timestep, and a final
time with units.
2. Euler updates the next state from the current state and current rate; trace the first steps before
trusting a loop.
3. Compare timesteps with an independent reference and test the initial value and physical trend before
interpreting a numerical trajectory.
Preparation for the practical. For each supplied ODE context, identify the state and rate,
label the initial condition and units, trace two Euler steps, then record an initial-value/trend check
plus a timestep or reference comparison before explaining the output.
